# AGENTS.md — Внешний мозг (external-brain)

Простое PWA для списка дел: строки с отступами (группы), выполнение, время
задачи, история ↩↪, копии, офлайн-синк через GitHub. Модель: статусы `inbox/next/done` живут в `src/logic.js` и синке
(`waiting`/`someday`, поле `project`, `focusTask` удалены в v76, нарезка —
в v77; в живых задачах не использовались).
Репозиторий: `git@github.com:russkin/external-brain.git`, ветка `main`.
Прод: https://russkin.github.io/external-brain/ (GitHub Pages, source = GitHub Actions).
ЖИВЫЕ ДАННЫЕ: `kalugin-a/brain-data` (`data/state.json`, ветка `main`, приватный
репозиторий) — диагностику (файл состояния, `logs/`) смотреть ТАМ, не в
russkin/external-brain. Код по умолчанию смотрит в russkin/external-brain —
дефолты в коде не менять. Переезд на личный репозиторий остаётся возможным
через настройку repo в приложении.
Текущая версия: v88 (октябрь 2026). Тестов: 142 (`logic` + `ios` + `sync` + `sync-devices`).
Тестовая платформа: смартфон Honor 400 Pro, Android 16 (планшет в этом проекте НЕ
используется — все замечания и проверки идут на телефоне).

Граница: приложение личное — single-user на одном телефоне (один пользователь,
один токен, один файл состояния), совместное использование не планируется
(non-goal). Multi-device без гарантий: sync-devices-тесты остаются только как
защита слияния. iOS/планшет/другие браузеры — «как получится», без обещаний
и ручных проверок. Полный список non-goals (NG-01…NG-14) — в
`specs/requirements.md` §5.2, метрики не ведутся (решения H-01…H-10 от
2026-10-06).

Связь с `alex/purchases`: только историческая — при создан external-brain как копия
purchases, но проекты РАЗОШЛИСЬ и независимы: разные репозитории, разные
`data/state.json`, общего кода нет (каждый файл-копия правится отдельно).
Фиксы и «грабли» между проектами НЕ переносятся — каждый баг лечится у себя.

## Регламент публикации (обязательный после КАЖДОГО коммита)

1. `node --test tests/logic.test.js tests/ios.test.js tests/sync.test.js tests/sync-devices.test.js` — всё зелёное.
2. Покрытие: `node --test --experimental-test-coverage ...` — logic.js/sync.js ≥90% строк и ≥89% веток (UMD-хвост `else if (typeof window…)` в Node не покрыть — H-11).
3. `git commit`, затем push. Прямой push без токена не взлетит (origin — SSH):
   `git push "https://x-access-token:${GITHUB_TOKEN}@github.com/russkin/external-brain.git" main:main`
   Токен брать из локального `.env` (`GITHUB_TOKEN`), в выводе затирать через
   `sed -E 's/x-access-token:[^@]+@/x-access-token:REDACTED@/g'`.
   При `rejected` — `fetch + rebase origin/main + push`, повторы до успеха.
4. Дождаться workflow «Deploy PWA to GitHub Pages» (`completed/success`) через Actions API.
   Учти `concurrency.cancel-in-progress`: первый запуск может быть `cancelled`, жди следующий.
5. Проверить прод curl'ом (200 + маркеры новой версии в `app.js`/`sw.js`).
6. Сообщить пользователю: опубликованную версию (`APP_VERSION`) и адрес https://russkin.github.io/external-brain/

## Версии

`APP_VERSION` в `app.js` и `CACHE = 'extbrain-vN'` в `sw.js` — менять ВМЕСТЕ при любом
изменении кода приложения (иначе устройства не поймут, что обновились).
Версия видна в шапке (`#appVerHead`). Service worker: skipWaiting +
clients.claim, приложение само перезагружается при смене контроллера.
Docs-only правки версию НЕ bump'ят. Есть регресс-тест на совпадение меток.

- `tests/` — `logic.test.js`, `ios.test.js` (строковые регрессы app.js/index.html/sw.js),
  `sync.test.js`, `sync-devices.test.js` (фейковый GitHub с sha-семантикой).
- `docs/USER_GUIDE.md` (+ `.html` для офлайна, ссылка из ⚙), `README.md`.

## Протокол синка (методология из alex/purchases)

- У каждой задачи своя метка `ts`, ставится при любом изменении.
- `mergeTasks`: для каждой задачи побеждает свежая `ts`, при равных — локальная.
- Удаление — tombstone (`deleted: true`): мёртвая задача с более свежей `ts`
  побеждает живую, иначе удаление на одном устройстве воскрешало бы задачу с другого.
- `syncNow` (`sync.js`): GET → merge → PUT merged если отличается
  (`pushed`/`merged`/`pulled`/`in-sync`). 409/422 → до 5 ретраев с экспоненциальным
  backoff + джиттер (настраивается 3-м аргументом фабрики в тестах).
  Токен — только из настроек устройства.
- `doSync` (`app.js`): single-flight (летит один, повтор ждёт очереди).
  Любая ошибка → ещё 5 повторов через 2 сек. Без сети повторы не тратятся впустую
  (триггеры — только по событиям + опрос).
- Триггеры: debounce 2 сек после каждого изменения, фоновый опрос раз в 60 сек
  (только если вкладка видима + сеть + токен), при открытии, при возврате на вкладку
  (`visibilitychange` + `focus` + `pageshow`, троттлинг 15 сек), при появлении сети,
  пункт ⚙ → «Синхронизировать», тап по светофору.
- Без токена синк молча ничего не делает (это НОРМА для одного устройства).
- Одновременная правка одной задачи с двух устройств — побеждает поздняя (файловый sync, не CRDT).
- `cloneTask` (`logic.js`) обязан копировать **ВСЕ** поля задачи: в v64 он терял
  `estMin` — любое слияние стирало все метки времени (в т.ч. при равных ts),
  включая файл на сервере, а восстановление «съедалось» следующим же синком
  (статус `pulled`). Регресс-тест — в `logic.test.js` («свежая ts побеждает»).
- Проверка новой версии (`checkUpdate`): качает `app.js?nocache=` мимо кэша SW
  (в sw.js явный bypass), при открытии и возврате на вкладку, не чаще раза в 5 минут.
  Находит новее — спрашивает и чистит кэш сам. Плюс `pokeSwUpdate`: при возврате
  на вкладку дёргает `reg.update()`.
- Пустое состояние никогда не затирает непустое (`mergeDecision`: pull/push/in-sync).

## UI-договорённости (не ломать молча)

- Своя модалка (`askText`/`askConfirm`): `prompt/confirm` на iOS Chrome вне
  user-activation блокируются — есть регресс-тест.
- Разделитель «Выполнено · N» — тап скрывает/показывает секцию выполненных
  (`toggleDoneHidden`, локальный ключ `external-brain-done-hidden-v1`).
  В скрытом состоянии строки не рендерятся, но сам разделитель остаётся —
  он же точка возврата и кламп дыры (`fr[phi].sep`) при перетаскивании.
- Родителю (есть вложенные) время ставить нельзя: `openDuration` закрыт
  `hasKidsFull` — и свайп вправо, и тап по метке. Метка родителя —
  авто-сумма первого вложения (`lineEstMin`: дети уровня indent+1,
  рекурсия; выполненные вложения в сумму НЕ входят — v71, иначе чип
  «всё равно считал» done), своё estMin родителя в вёрстку не идёт
  (данные не трогаем — без детей задача снова показывает своё).
- Локальная копия состояния (`store.js`, ключ `external-brain-backup-v1`):
  перед КАЖДОЙ записью предыдущее сохранённое состояние уходит в
  localStorage («на шаг позади»). Восстановление — ⚙ → «♻ Восстановить
  копию задач» (через `mutate`, отмена ↩; только задачи, настройки/токен
  не трогаем). `restoreBackup()` ставит `skipBackupOnce`, иначе акт
  восстановления перетёр бы хорошую копию текущим состоянием.
  ⚠ Копия «на шаг позади» НЕ спасает от медленной порчи: частые сохранения
  (авто-синк) двигают её вперёд (так в v64 затёрлась копия без меток) —
  для этого есть ПОСТОЯННАЯ («вечная») копия, ключ `external-brain-pin-v1`:
  ⚙ → «💾 Сделать постоянную копию» (перезапись только с подтверждением)
  и «♻ Восстановить постоянную копию»; плюс авто-пин `pinOnVersion(APP_VERSION)`
  при первом запуске новой версии (запоминает версию в
  `external-brain-pin-ver-v1`, создаёт копию ТОЛЬКО если её ещё нет —
  ручную никогда не перетирает). В копию уходят ТОЛЬКО задачи — без
  настроек и токена (`pinWrite` пишет `{ tasks }`). Обе кнопки в ⚙,
  дата в диагностике («Постоянная копия: … (вручную / перед vNN)»).
- История отмены/возврата (↩ ↪, до 50 шагов) переживает перезагрузку и
  обновление: обе стопки лежат в localStorage (`external-brain-undo-v1` /
  `external-brain-redo-v1`). Единственная точка записи нового шага —
  `pushUndo()` (сбрасывает redo и сохраняет обе стопки); `doUndo`/`doRedo`
  дёргают `histSave()`;   `histLoad()` при старте чистит битые записи
  (запись без строкового `tasks` отбрасывается).
- Задачи с пустым текстом — полноценные строки (v68): `createTask` принимает
  `{ allowEmpty: true }` (по умолчанию пустое имя — как раньше `null`);
  `clarifyTask` применяет пустой `title`; `isAlive` текст не проверяет.
  Пустая создаётся Enter в черновике ИЛИ тапом мимо с пустым полем
  (v70: blur фиксирует поле и с текстом, и пустое — но пустое ТОЛЬКО при
  свежем `pointerdown`: программный blur (`toggleDoneSlide` снимает фокус
  принудительно, клавиатура ушла) пустую не плодит, guard
  `if (!title && !fresh) return;` — без него seed плодил мусорную пустую).
  Удаляется Backspace в пустой строке (`mergeTaskIntoPrev`). На пустой
  строке Enter открывает поле ПОД ней (в пустой каретка всегда в «начале»,
  но `atStart` требует непустого текста — иначе вторая пустая прыгала бы
  выше первой). `lineTasks`/`fullList` пустые показывают — строка
  участвует в перетаскивании и порядке как обычная (пустая как раз и
  чинит старый баг «drag при пустой строке откатывался»); `stats`,
  `inboxCount` пустые НЕ считают (в диагностике их нет —
  без них), `shareText` тоже исключает. Плейсхолдер: у задачи `…`,
  у черновика `Новая задача…`. Пустые строки видны только на ≥v68: старые
  версии их не показывают (фильтр в `lineTasks`), но каталог не ломают —
  держать все устройства обновлёнными, прежде чем плодить пустые.
- Якорь черновика после драга (v70): если задачу тащили ЧЕРЕЗ поле,
  `data-id`-порядок может не измениться → `persistLineOrder` no-op →
  render возвращал поле на старый якорь («всё возвращается на свои места»).
  Поэтому в `finish()` после drop поле пересчитывается по DOM: якорь —
  живая строка непосредственно над черновиком (или `TOP`), отступ по
  соседям; если порядок задач уже переставлен, второй undo-слепок не
  плодим (`reordered` из `persistLineOrder()` — она теперь возвращает
  булево).
- Диагностика ⓘ и чистка legacy-поля `frog` (v72): `diagText()` стал промисом — строка
  «Обновление: SW …, кэш extbrain-*» собирается асинхронно (`diagSwInfo()`,
  `caches.keys()`), обработчик `#diagBtn` показывает текст через `.then`.
  Содержимое: «Задач: N · готово M» (без постатусного списка), размер каталога
  (записей/КБ), синк со временем успеха и строка ошибки (localStorage
  `external-brain-synclog-v1`, пишется в `doSync`, переживает F5), время
  каталога (`state.updatedAt` ставится в `mutateWithHistory`/`applySnapshot`
  и при pull), локальные флаги (выполненные скрыты, свёрнуто групп), счётчики
  ↩↪, сеть (`navigator.connection`), устройство (парс UA), последнее действие.
  Поле `frog` выпилено из модели: `setFrog`/`hasFrog`/сортировка next по
  frog/FROG-префикс удалены, старые данные с `frog` нормализация молча
  отбрасывает; мёртвые `taskRow`/`renderGroup` в app.js удалены (единственный
  вызов `L.reopenTask(state.tasks` жил там — живой возврат через
  `reopenBranch`, тесты поправлены на него).
- Окно диагностики как в purchases (v73): показ через свою `showInfo(title,
  body, shareable)` — кнопки **OK + Поделиться**, поле ввода и «Отмена» скрыты;
  `shareDiag` — `navigator.share` → буфер («Готово, скопировано») → ручное
  копирование в окне. Закрытие `showInfo` возвращает дефолты кнопок (иначе
  следующий `askText` показал бы «Поделиться» вместо «Очистить»). Внизу текста
  — «Журнал:» последних 12 синк-событий (как journal.js в purchases):
  `syncLogPush` в `doSync` пишет «синк: <статус>» и «ошибка синка: <текст>»,
  кольцо 50 в localStorage `external-brain-synclog-v1` (тот же ключ с
  временем синка/ошибки, обратно совместим со старым форматом).
- Светофор «!» и сеть ⇅ как в purchases (v74): `setLight` при ошибке
  `github-put (409|422)` показывает красный «!» (класс `alert`, класс
  `#syncLight.alert` в index.html), тап по светофору — принудительный синк;
  новая `renderNet()` обновляет ⇅ (зелёный/серый по online/offline) и подпись
  скорости (`navigator.connection.downlink/8` → МБ/с), подписки online/
  offline/connection change в `wire()`. Мёртвый код purchases исключён:
  CSS `.group`/`.group-title`/`.row-name`/`.row-name.done`, экспорты
  `STATUSES`/`makeId`/`MAX_INDENT` из api `src/logic.js`. Журнал синка хранится
  локально (localStorage `external-brain-synclog-v1`, «Журнал:» в
  диагностике ⓘ).
- Публикация журнала на сервер (v75, как в purchases): при ошибке синка с
  `github-` в тексте (сетевые обрывы не публикуем — сети нет и для публикации)
  вызывается `maybePublishJournal()`: не чаще раза в 15 минут (иначе спам
  коммитами), файл в сутки `logs/sync-ГГГГ-ММ-ДД-<device>.json` (device —
  случайный id в localStorage `external-brain-device-v1`), тело
  `{ device, version, at, journal }` (последние 50 записей) через `publishFile`.
  Статус/время публикации пишутся в synclog (`pubAt`/`pub`) и видны в
  диагностике: строка «Публикация журнала: …», id устройства — в «Устройство:».
  Лог-коммиты деплой не триггерят (`paths-ignore: data/**, logs/**`).
- Вертикальный drag (v69, грабль): `grabDy` (сдвиг «призрака» и `dt` для
  дыры) меряется в `pointerdown` по позиции захвата, НЕ в `startVertical` —
  там палец уже уехал на 14+px (на таче первый `pointermove` ещё крупнее),
  `dt` смещался вниз, дыра не добирала до целевого слота: задача садилась
  строкой ниже целевой (а при цели в соседе — на своё место, «ничего не
  происходит»). Ловится длинными драгами и прицеливанием в вершину списка.
- Repo и токен — за пунктом «🔑 Репозиторий и токен» с предупреждением
  «только для администратора» (как в purchases): блок `gearSettings`
  скрыт до подтверждения, закрывается при закрытии меню и при «Сохранить».
- Все подписки только через защищённый `on(id, ev, fn)` (пропускает отсутствующие
  элементы при рассинхроне кэшей) — есть регресс-тест.
- В функции логики передавать `state.tasks`, НЕ `state` — есть регресс-тест.
- Поле токена живёт в DOM только при открытых настройках (иначе Chrome предлагает
  сохранить токен как логин) — есть регресс-тест.
- Светофор (`#syncLight`): зелёный/жёлтый мигающий/красный/серый; при
  409/422 — красный «!» (класс `alert`); тап — принудительный синк.
- Сеть (`#netStatus` ⇅ + `#netType`): `renderNet()` — цвет по online/offline,
  подпись — скорость (downlink/8 → МБ/с, на iPhone пусто); обновляется по
  online/offline/connection change и при каждом `renderStatus`.
- Время задачи: поле `estMin` (минуты, 0..59999) в whitelist `normalizeTask`
  (иначе старая версия сотрёт при синке); метка `.durchip` — absolute-наложение
  в правом нижнем углу ПОЛЯ задачи, только при estMin>0; формат `L.fmtDur`
  (`30 м` / `1ч` / `1ч 30м`). Флаг `✓` (z-index 2) всегда поверх метки (z-index 1).
  Фон метки: прозрачный по умолчанию; если последняя строка текста поля
  доезжает до метки — `updateDurchip` делает его непрозрачным (background-color
  поля), иначе два текста слипаются. Замер — зеркалом поля (span-маркер после
  текста, как getCaretCoordinates), вызывается из renderLines (`refreshDurchips`),
  обработчика input и debounced resize (клавиатура/поворот).
  Открытие: свайп строки вправо (порог dx>48, флаг `_swRArm`, модалка на
  pointerup) или тап по метке → `askDuration` (часы ±60, минуты ±5 от общего
  `durTot`, кнопки стрелок подписаны в `wire()` через `on()`); «Убрать» → 0.
  После свайпа 400 мс гасятся кличи (`_swBlockUntil`) — отпускание часто
  попадает в метку, иначе вторая модалка/фокус в поле.
  Возврат из-под раскрытого флага вправо ВРЕМЯ НЕ ОТКРЫВАЕТ: на старте
  жеста и при раскрытии флага ставится `swHadFlag` — один жест либо
  закрывает флаг, либо (чистый свайп вправо) открывает время, не оба.

7. Каталог `alex/external-brain` пересоздан под пользователя opencode (исходный был

    уезжает вверх при drag'е, пересечённые строки оказываются ниже него («улетели
    в раздел выполненных»). Дыру клампить перед разделителем (`fr[phi].sep`) —
    живая задача в секцию выполненных не садится. Ловится только в настоящем
    браузере (jsdom вёрстки не даёт) — репро на puppeteer с замером `sep.top`.

    `applyDropIndent` меняет ТОЛЬКО данные — без `dropMargins(div, kids)` в том же
    кадре строка и дети носят отступ 0/старый до `render` (220мс) и прыгают уже

12. Каркас drag'а (`fr`) проверял только инлайн `display:none`, а свёрнутые дети
    прячутся КЛАССОМ `collapsed-kid`: каждый спрятанный давал фантомный зазор

    движении вниз мимо свёрнутых групп («над 8-й, а раздвинулись 6 и 7»).

    по видимым детям (`visKids`); скрытые дети в `kids[]` остаются (финиш
