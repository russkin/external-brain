## 1. Цель и метрики успеха

### 1.1 Цель

Личный офлайн-список дел для одного человека на одном телефоне: ввод задачи — одна строка, группа — отступ, выполнение — свайпом, оценка времени — меткой в углу поля, изменение отменяется стрелкой, данные переживают сбой синка, обновление приложения и потерю связи. Хостинг — GitHub Pages, синк через GitHub Contents API — необязательная опция (для бэкапа/переноса), включается вручную. Решение H-01 (2026-10-06): целевой сценарий — одно устройство.

Модель данных унаследована от «Джедайских техник» (`src/logic.js`, doc-комментарий 1–15), но **фактический интерфейс v75 — плоский список строк**: статусы, проекты и нарезка из UI не управляются (README:20–22, AGENTS.md:3–7).

### 1.2 Метрики успеха

Метрики не ведутся — решение H-09 (2026-10-06): «и так всё понятно». Обязательным остаётся только регламент публикации (все тесты зелёные перед каждым коммитом, покрытие `logic.js`/`sync.js` ≥ 90%).

### 3.12 Синхронизация

- **FR-61. Синк необязателен.** Без токена `syncNow` возвращает `no-token`, сеть не трогается; в статусе — «выключен (нет ключа)», светофор серый. Это **норма** для одного устройства.
  *Проверка:* `sync.test.js` «без токена — no-token, сеть не трогаем».
- **FR-62. Хранилище общего состояния:** `data/state.json`, ветка `main`, форма `{ updatedAt, tasks }`. Код по умолчанию смотрит в `russkin/external-brain` (`store.js:148, 161`), но ЖИВЫЕ ДАННЫЕ — в приватном репозитории `kalugin-a/brain-data` (решение H-02, 2026-10-06; репозиторий приложения публичный, данные — нет). Дефолт в коде не менять.
  *Проверка:* `ios.test.js` «файл состояния — data/state.json».
- **FR-63. Алгоритм `syncNow`:** GET (`cache: 'no-store'` мимо HTTP-кэша) → `mergeTasks` (позадачный LWW) → PUT, только если объединение отличается от удалённого. Статусы: `pushed` / `merged` / `pulled` / `in-sync`; при 404 и непустом локальном состоянии — PUT без sha → `pushed`.
  *Проверка:* `sync.test.js` — «файла нет + локально пусто — in-sync без PUT», «файла нет + локально есть данные — pushed без sha», «удалённый новее — pulled», «локальный новее — pushed с sha», «одинаковые — in-sync без PUT», «правки с обеих сторон — merged».
- **FR-64. Ретраи и таймауты:** 409/422 → до 5 попыток с экспоненциальным backoff (base 800 мс, cap 8000 мс, джиттер ≤ 300 мс; настраивается `opts` фабрики, включая `sleep`); прочие ошибки — сразу в `error`; таймаут `fetch` —20 сек через гонку `Promise.race` (`timedFetch`, совместимо со старыми WebView без `AbortController`).
  *Проверка:* `sync.test.js` — «409 — ретрай, затем успех», «409 исчерпан — error», «не-409 ошибка PUT — сразу error», «ошибка GET — error без исключений», «битый ответ без content — error», «таймаут fetch — error», «обрыв fetch — error», «409 с дефолтным сном — ретрай, затем успех».
- **FR-65. Правила слияния:** для каждой задачи побеждает более свежая `ts`, при равных — локальная; удаление — tombstone; **пустое состояние никогда не затирает непустое** (`mergeDecision`: `pull` / `push` / `in-sync`).
  *Проверка:* `logic.test.js` «свежая ts побеждает, равные — локальная», «удаление побеждает только свежей меткой», «mergeDecision: пустое не затирает», «tasksEqual и isTasksEmpty».
- **FR-66. `cloneTask` обязан копировать ВСЕ поля, включая `estMin`** (v64: любое слияние стирало все метки времени, включая файл на сервере, а «восстановление» съедалось следующим же синком со статусом `pulled`).
  *Проверка:* `logic.test.js` «свежая ts побеждает, равные — локальная»; комментарий AGENTS.md:86–89.
- **FR-67. Порядок в приложении (single-flight):** летит один синк, повтор ждёт в очереди (`syncFlying`/`syncQueued`) — иначе вечные 409 на медленной сети; ошибка → ещё 5 повторов через 2 сек, счётчик сбрасывается успехом; успех `pulled`/`merged` → сохранение состояния и рендер.
- **FR-68. Триггеры синка:** debounce 2 сек после каждого изменения (все мутации идут через `save()`), при открытии, при возврате на вкладку (`visibilitychange` + `focus` + `pageshow`, троттлинг 15 сек), при появлении сети (`online` → принудительный), ⚙ → «⇅ Синхронизировать», **тап по светофору**, фоновый опрос раз в 60 сек (только вкладка видима + сеть + токен).

## 4. Нефункциональные требования

- **NFR-01. Офлайн-first.** Приложение полностью работоспособно без сети: данные — IndexedDB (`external-brain`, store `state`) с fallback на `localStorage` (`external-brain-v1`); оболочка — в кэше SW; открытие установленного ярлыка показывает список без интернета. Синк — единственная сетевая функция, и она необязательна.
- **NFR-02. Устойчивость рендера на телефоне.** Позиция страницы сохраняется при рендере (`keepY`/`scrollTo`); рендер подавлен во время жеста (`dragActive`); вьюпорт не прыгает при захвате (пин прокрутки, фокус снимается только в `finish`); автоскролл только при уверенном движении; многострочные поля раскрываются по содержимому.
- **NFR-03. Стойкость к рассинхрону кэшей.** Все подписки только через защищённый `on(id, ev, fn)` (пропускает отсутствующий элемент) — старый `index.html` + новый `app.js` не роняют приложение.
  *Проверка:* `ios.test.js` «все подписки через защищённый on()», «прямая подписка без on()» (regex).
- **NFR-04. Корректность вызовов логики.** В функцию логики передаётся `state.tasks`, **не** `state`.
  *Проверка:* `ios.test.js` describe «логика вызывается с state.tasks» — «мутации получают state.tasks, а не state», «стартовый экран: строки читаются из state.tasks».
- **NFR-05. Предсказуемость сетевых вызовов.** Таймаут любого fetch — 20 сек; один синк за раз (single-flight); ретраи с backoff; `no-store` на GET (браузер кэширует ответы Contents API до минуты — иначе устройство рапортует `in-sync` со старым); установка SW строго из сети.
- **NFR-06. Приватность по умолчанию.** Токен — только на устройстве (в DOM только при открытых настройках); в постоянную копию уходят **только задачи**; публикуемый журнал содержит `{device, version, at, тексты событий}` и **не содержит содержимого задач**; аналитики/трекеров нет (`Notification`, push, внешние счётчики — отсутствуют).
  *Открытый риск:* личный список дел лежит в `data/state.json` **того же репозитория**, что и приложение, и журнал публикуется в `logs/` **того же** репозитория → вопрос **H-02** (приватность репозитория).
- **NFR-07. Тестируемость.** 137 тестов (`logic` + `ios` + `sync` + `sync-devices`), покрытие `logic.js`/`sync.js` ≥ 90 % строк и веток; запуск — **перечислением файлов** (`node --test tests/… `), папкой в этом окружении падает (AGENTS.md:253). Проверка UI/жестов — только вручную на FR-02; DOM-тестов нет.
- **NFR-08. Русский язык и базовая доступность.** Весь интерфейс и инструкция — на русском; у интерактивных элементов строк есть `aria-label`/подсказки («Тащить», «Отметить выполненной», «Вернуть в работу», «Время задачи: …»).

**H-01. Single-user = одно устройство или несколько личных устройств одного человека?**
*Факты:* AGENTS.md:14–15 говорит «один пользователь, один токен, один файл состояния» (не ограничивает число устройств); README:59–64 и `docs/USER_GUIDE.md:157–174` описывают «синхронизацию между устройствами» и рекомендацию «держите все устройства на свежей версии»; есть `tests/sync-devices.test.js` (4 сценария); `diagText` печатает «Устройство: … · id <device>» и журнал пишется по device-id — то есть несколько устройств архитектурно заложены.
*Варианты:* (A) **одно устройство — целевой сценарий**, синк «на всякий случай/для бэкапа», multi-device — побочный режим без гарантий; (B) **несколько личных устройств — поддерживаемый сценарий**, тогда нужен раздел про «перенос на новый телефон» и критерий «все на свежей версии»; (C) два устройства максимум.
*Цена решения:* от неё зависят формулировки FR-71, H-05 и приоритет тестов `sync-devices`.

**H-02. Репозиторий `russkin/external-brain` — публичный или приватный?**
*Факты:* в нём лежат и опубликованное приложение, и `data/state.json` с полным личным списком дел, и `logs/sync-*.json` (метаданные + тексты ошибок). Локальная копия `data/state.json` — пустой seed `{"tasks":[],"updatedAt":0}`; реальные данные пишутся на сервер мимо git.
*Варианты:* (A) **приватный** — синк работает с personal access token, всё в порядке, требование «не публиковать личные дела» выполняется архитектурно; (B) **публичный** — тогда нужны отдельные приватные данные приложения (другой репо/ветка) либо явное согласие «список дел публичен».
*Цена решения:* NFR-06 и весь раздел приватности; при (B) — отдельная задача на развести данные и код.
