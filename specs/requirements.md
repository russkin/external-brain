## 1. Цель и метрики успеха

### 1.1 Цель

Личный офлайн-список дел для одного человека на одном телефоне: ввод задачи — одна строка, группа — отступ, выполнение — свайпом, оценка времени — меткой в углу поля, изменение отменяется стрелкой, данные переживают сбой синка, обновление приложения и потерю связи. Хостинг — GitHub Pages, синк через GitHub Contents API — необязательная опция (для бэкапа/переноса), включается вручную. Решение H-01 (2026-10-06): целевой сценарий — **одно устройство**.

Модель данных — плоский список строк как задачи в Google Keep (`src/logic.js`): только статусы `inbox/next/done`, лишнее (статусы, проекты, нарезка, фокус дня) удалено и из UI не управляется.

### 1.2 Метрики успеха

Метрики не ведутся — решение H-09 (2026-10-06): «и так всё понятно». Обязательным остаётся только регламент публикации: 136/136 тестов зелёные перед каждым коммитом + покрытие `logic.js`/`sync.js` ≥ 90% строк и ≥ 89% веток (решение H-11: UMD-хвост в Node не покрыть).

### 3.6 Порядок, группы, перетаскивание

- **FR-29. Точки ⠿ — вертикальный drag:** строка едет, соседи разъезжаются (дыра), родитель едет с детьми, **выполненные не таскаются**, страница стоит на месте (пин прокрутки на время жеста), клавиатура закрывается **после** `pointerup`, а не на захвате.

- **FR-30. `grabDy` меряется в `pointerdown`** (v69), иначе дыра не добирает до целевого слота и задача садится строкой ниже.
  *Проверка:* `ios.test.js` assert «grabDy меряется в pointerdown, а не при старте режима» (в it «глобальные ошибки видны в статусе»).
- **FR-31. Живая задача не садится в раздел «Выполнено»:** дыра клампится по разделителю `fr[phi].sep` (сам разделитель участвует в каркасе drag’а). **Каркас считает только видимые строки** (v78): свёрнутые дети прячутся классом `collapsed-kid` и в каркас не идут — иначе дыра «плывёт» мимо свёрнутого родителя.
  *Проверка:* `ios.test.js` «каркас drag не считает спрятанных классом: дыра не плывёт мимо свёрнутых», «групповой drag: дети прячутся под родителя и едут с ним»; ручная на FR-02 (jsdom вёрстку не даёт — AGENTS.md:279–284).
- **FR-32. Запись нового порядка (`persistLineOrder`, `app.js:1713–1787`):** перенумеровывается `createdAt` непрерывным блоком отличий; при исчерпанном зазоре — перенумеровываются все живые (выполненные не трогаются); затронутым ставится свежий `ts`; **вторая запись в историю не плодится** (возвращается `reordered`). Слепок истории — досдвиговый (`preDrop = snapFull()` до `applyDropIndent`, `app.js:2341`), иначе ↩ возвращал порядок без отступа; чистое изменение отступа без сдвига порядка пишется тем же слепком (`app.js:2381, 2385–2386`).
  *Проверка:* `ios.test.js` assert «нет пересчёта якоря черновика после драга» (`var reordered = persistLineOrder(preDrop)`), «нет досдвигового слепка перед applyDropIndent», «persistLineOrder не принимает досдвиговый слепок», «чистое изменение отступа без сдвига порядка не пишется в историю», «перетаскивание пустого поля пишется в историю».
- **FR-33. Отступ после drop** считается по соседям на новом месте (`applyDropIndent`, `app.js:1789`), весь перетащенный блок сдвигается на дельту; `dropMargins` (`app.js:1824`) применяется в том же кадре (иначе строки носят старый отступ до `render`).
- **FR-34. Якорь черновика после drag’а через поле пересчитывается по DOM** (v70), иначе `data-id`-порядок не меняется, `persistLineOrder` — no-op, и всё «возвращается на свои места» (`trailingAfterId = newAfterB`).
- **FR-35. Сдвиг за точки влево/вправо** — вход в группу верхней задачи / выход из неё (`mode = 'indent'`, `app.js:1890+`, `lastDx / INDENT_STEP` `app.js:2209`); новое поле всегда начинается без отступа; сдвиг идёт от пальца.
  *Проверка:* `ios.test.js` «отступ по месту отпускания: родители→0, внутри→от соседа», «группы отступом: сдвиг за grip, наследование, потолок +1».

### 3.12 Синхронизация

- **FR-61. Синк необязателен.** Без токена `syncNow` возвращает `no-token`, сеть не трогается; в статусе — «выключен (нет ключа)», светофор серый. Это **норма** для одного устройства.

- **FR-62. Хранилище общего состояния:** `data/state.json`, ветка `main`, форма `{ updatedAt, tasks }`. Код по умолчанию смотрит в `russkin/external-brain` (`store.js:148, 161`), но **ЖИВЫЕ ДАННЫЕ — в приватном репозитории `kalugin-a/brain-data`** (решение H-02, 2026-10-06; репозиторий приложения публичный, данные — нет). Дефолт в коде не менять.
  *Проверка:* `ios.test.js` «файл состояния — data/state.json».
- **FR-63. Алгоритм `syncNow`:** GET (`cache: 'no-store'` мимо HTTP-кэша) → `mergeTasks` (позадачный LWW) → PUT, только если объединение отличается от удалённого. Статусы: `pushed` / `merged` / `pulled` / `in-sync`; при 404 и непустом локальном состоянии — PUT без sha → `pushed`.
  *Проверка:* `sync.test.js` describe «syncNow: базовые исходы» — «файла нет + локально пусто — in-sync без PUT», «файла нет + локально есть данные — pushed без sha», «удалённый новее — pulled», «локальный новее — pushed с sha», «одинаковые — in-sync без PUT», «правки с обеих сторон — merged».
- **FR-64. Ретраи и таймауты:** 409/422 → до 5 попыток с экспоненциальным backoff (base 800 мс, cap 8000 мс, джиттер ≤ 300 мс; настраивается `opts` фабрики, включая `sleep`); прочие ошибки — сразу в `error`; таймаут `fetch` — 20 сек через гонку `Promise.race` (`timedFetch`, совместимо со старыми WebView без `AbortController`).
  *Проверка:* `sync.test.js` describe «syncNow: конфликты и ошибки» — «409 — ретрай, затем успех», «409 исчерпан — error», «не-409 ошибка PUT — сразу error», «ошибка GET — error без исключений», «битый ответ без content — error», «таймаут fetch — error», «обрыв fetch — error», «409 с дефолтным сном — ретрай, затем успех».
- **FR-65. Правила слияния:** для каждой задачи побеждает более свежая `ts`, при равных — локальная; удаление — tombstone; **пустое состояние никогда не затирает непустое** (`mergeDecision`, `logic.js:458`: `pull` / `push` / `in-sync`).
  *Проверка:* `logic.test.js` «свежая ts побеждает, равные — локальная», «удаление побеждает только свежей меткой», «mergeDecision: пустое не затирает», «tasksEqual и isTasksEmpty».
- **FR-66. `cloneTask` обязан копировать ВСЕ поля, включая `estMin`** (`logic.js:403`; v64: любое слияние стирало все метки времени, включая файл на сервере, а «восстановление» съедалось следующим же синком со статусом `pulled`).

Порядок в приложении (single-flight):** летит один синк, повтор ждёт в очереди (`syncFlying`/`syncQueued`) — иначе вечные 409 на медленной сети; ошибка → ещё 5 повторов через 2 сек (`doSync`, `app.js:457–501`), счётчик сбрасывается успехом; успех `pulled`/`merged` → сохранение состояния и рендер.

## 4. Нефункциональные требования

- **NFR-01. Офлайн-first.** Приложение полностью работоспособно без сети: данные — IndexedDB (`external-brain`, store `state`) с fallback на `localStorage` (`external-brain-v1`, `store.js`); оболочка — в кэше SW; открытие установленного ярлыка показывает список без интернета. Синк — единственная сетевая функция, и она необязательна.
- **NFR-02. Устойчивость рендера на телефоне.** Позиция страницы сохраняется при рендере (`keepY`/`scrollTo`); рендер подавлен во время жеста (`dragActive`); вьюпорт не прыгает при захвате (пин прокрутки, фокус снимается только в `finish`); автоскролл у краёв — по таймеру `edgeTick` (20мс, шаги 3→5px — плавно; стоящий палец тоже крутит, дыра пересчитывается, пин — с реального смещения, таймер гасится на финише); многострочные поля раскрываются по содержимому.
  *Проверка:* `ios.test.js` «позиция страницы не прыгает, автопрокрутка не дёргает».
- **NFR-03. Стойкость к рассинхрону кэшей.** Все подписки только через защищённый `on(id, ev, fn)` (пропускает отсутствующий элемент) — старый `index.html` + новый `app.js` не роняют приложение.
  *Проверка:* `ios.test.js` describe «устойчивость к рассинхрону кэшей» — it «все подписки через защищённый on()» + assert «прямая подписка без on()» (regex).
- **NFR-04. Корректность вызовов логики.** В функцию логики передаётся `state.tasks`, **не** `state`.
  *Проверка:* `ios.test.js` it «мутации получают state.tasks, а не state», «стартовый экран: строки читаются из state.tasks».
- **NFR-05. Предсказуемость сетевых вызовов.** Таймаут любого fetch — 20 сек (`timedFetch`); один синк за раз (single-flight); ретраи с backoff; `no-store` на GET (браузер кэширует ответы Contents API до минуты — иначе устройство рапортует `in-sync` со старым); установка SW строго из сети.
- **NFR-06. Приватность по умолчанию.** Токен — только на устройстве (в DOM только при открытых настройках); в постоянную копию уходят **только задачи**; публикуемый журнал содержит `{device, version, at, тексты событий}` и **не содержит содержимого задач**; аналитики/трекеров нет (`Notification`, push, внешние счётчики — отсутствуют). Данные живут в приватном `kalugin-a/brain-data` (H-02).
- **NFR-07. Тестируемость.** **136 тестов** (`logic` 51 + `ios` 60 + `sync` 22 + `sync-devices` 4; 19 suites), покрытие `logic.js` **99.60 лин / 89.95 веток / 100 funcs**, `sync.js` **98.48 / 91.21 / 100** (порог AGENTS.md:34 — строки ≥90%, ветки ≥89%, факт 89.95% ⇒ **H-11 закрыт**). Запуск — **перечислением файлов** (`node --test tests/…`), папкой в этом окружении падает (AGENTS.md:262). Проверка UI/жестов — только вручную на FR-02; DOM-тестов нет.
- **NFR-08. Русский язык и базовая доступность.** Весь интерфейс и инструкция — на русском; у интерактивных элементов строк есть `aria-label`/подсказки («Тащить», «Задача», «Отметить выполненной», «Вернуть в работу», «Время задачи: …», «Свернуть все группы», «Удалить выполненные» — `app.js:650, 842, 851, 854, 884, 915`, `index.html:131–135`).

**H-01. Single-user = одно устройство или несколько личных устройств одного человека?**
